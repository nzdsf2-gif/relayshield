RelayShield Attack Surface & Supply Chain API

SaaS, delivered as an HTTPS API. Entirely serverless, single region, one AWS account.
Single AWS account  ·  us-east-1
1 · Subscribe and fulfill
AWS MarketplaceBuyer subscribes and is redirected to our fulfillment URL with x-amzn-marketplace-token
↓ HTTPS
Amazon API GatewayREST API, TLS 1.2+, api.relayshield.net
↓
AWS Lambda, fulfillmentrelayshield-bundle-fulfillment. Calls ResolveCustomer and GetEntitlements, then issues the customer's API key
↓
Amazon DynamoDBAPI key record: customer identifier, product code, entitlement state. On-demand capacity, encrypted at rest
↓
Amazon SESDelivers the key to the buyer's registered address
2 · Serve a metered call
Customer applicationServer-to-server HTTPS with the issued API key
↓
Amazon API GatewayFive endpoints under /v1/metered/: supply-chain, asset-intel, secret-scan, threat-actor, session-risk
↓
AWS Lambda, APIrelayshield-api. Authenticates the key, checks the entitlement, runs the check
↓
Amazon DynamoDBIndicator corpus and watchlists. Read on every call; no customer request bodies are retained
↓
AWS Secrets ManagerUpstream data-source credentials, read at runtime. No credential is stored in code or configuration
3 · Meter, entitle, observe
AWS Marketplace MeteringBatchMeterUsage reports each successful call against its usage dimension. Only a 2xx is billed
↑
AWS Marketplace EntitlementGetEntitlements confirms the monthly commitment before access is granted
↓
Amazon SNSSubscription notification topic. Entitlement change, suspension and unsubscribe events
↓
AWS Lambda, fulfillmentSame function, SNS path. Deactivates the key when an entitlement lapses
↓
Amazon CloudWatch LogsStructured logs and metering outcomes. Identifiers are hashed before they are written
No EC2, no containers, no persistent compute. IAM roles are per-function and least-privilege; all data in transit is TLS, all data at rest is encrypted with AWS-managed keys.
