🛡︎ Verify a verdict receipt

Every RelayShield check can come with a signed verdict receipt — cryptographic proof of what was asked and what was answered. Paste one below and this page checks its signature entirely in your browser. Nothing you paste is sent anywhere; the math runs locally, so you don't have to trust us — or this page.

Receipts look like {"v":"rsr1", …}. You'll find one in the receipt field of any API check response.

How verification works

  1. You paste a receipt. It names the endpoint that was called, a hash of the input, the verdict, and when it was issued.
  2. You provide RelayShield's public key — pasted by hand, or fetched from our key endpoint. The private signing key never leaves our servers.
  3. Your browser re-hashes the receipt (every field except the signature, in a fixed canonical order) and checks the Ed25519 signature against the public key. If even one character was altered after signing, the check fails.
  4. You get an answer. Valid means RelayShield really issued exactly this verdict for exactly this input. Nothing more.
What verification does not prove: that the checked link, wallet, or email is safe. A valid receipt only proves the verdict is authentically ours — RelayShield never declares anything "safe".

Questions

Does RelayShield see what I paste?

No. The signature check runs with JavaScript on your device. The only network request this page ever makes is the optional key fetch, which downloads our public key — the same key anyone can read. Your receipt never leaves the page.

What if my receipt has no signature?

Then it was issued before we started signing verdicts. The page will tell you plainly: it can't be cryptographically verified, and that's expected for older receipts — not evidence of tampering.

Where do I get the public key?

Fetch it with the button above (it calls GET https://api.relayshield.net/v1/verdict-key), or paste one you obtained through another channel. If you're cautious, compare the fetched key against one you received out-of-band — the page shows you the key id it verified against.

What is "key id"?

Keys get replaced over time ("rotated"). Each receipt names the key that signed it (rsvk_…), so old receipts keep verifying against retired keys.

Which checks issue receipts?

All free check endpoints (link, wallet, email, breach, and the agent-facing endpoints) attach a receipt object to their response.
